# Regression guards from Ethan's review workflow

This index was checked against this chat's September–November 2026 session archives and the current source. Repeated reports are grouped by the behavior they protect. The owning code comments explain the local reason; this index points future agents to those owners and tests. It is not a claim that every historical lag report had the same cause or that API tests prove physical mouse acceptance.

Before changing an owner, read its comments and the linked neighboring cases. Preserve later corrections over earlier experiments. Do not restore a rejected implementation just because an old message requested it.

## Boundaries that must not be reported as completed fixes

- **SCM lookahead scrolling:** `scmReviewLookahead.ts` supplies the viewport planner and presentation-only queue; `macScmReviewLookahead.ts` and the bundled native worker connect it to the real Changes pane. Ethan's ten-row rule includes ordinary Next/Previous and Stage + Next, not just an eyes/explosion batch (1.2.154 missed that scope). Never substitute row walking or pointer-targeted clicks. Native tests must prove scrolling, unchanged selection/index/editor, restored pointer position after event delivery, and restoration of borrowed accessibility state even without a hold release. Pure planner checks alone or immediate pointer reads are insufficient.
- **Manual-only Staged Changes expansion:** VS Code 1.144's SCM tree creates every resource group expanded (`collapseByDefault`), filters an empty Staged group instead of letting it be focused, and runs Auto Reveal (`expandTo`) for a staged-only `file:` editor. There is no public API or setting for group expansion. Better Git removes its own staged-only `file:` trigger and folds visible Staged during Worktree links. It cannot guarantee a re-created group stays closed. Do not add background recollapse, focus-stealing group walks, polling or a global `scm.autoReveal` change.
- **Collapse unchanged lines:** VS Code's `diffEditor.hideUnchangedRegions.enabled` setting and its per-editor Show/Collapse commands have different scopes. This chat's suggested new mouse toggle was not silently implemented by the navigation changes above.
- **Personal setup:** monitor-based Inline/Automatic and zoom settings in `diffViewDisplay.ts` remain opt-in; the later re-enable decision supersedes the temporary Automatic-only request. Commit-model selection in `commitMessageModels.ts` remains Codex first, Claude fallback, newest recognized generation then smallest within it.
- **Other projects / operations:** Nest file icons belong to VSCode Icons++; the Angular package messages were explicitly redirected. Mini permissions/connectivity, Marketplace verification and normal-host activation belong to their operating instructions and release evidence, not guessed editor bug fixes.
- **Verification:** a successful upload, an installed directory, an API-controlled mouse command and a real physical hold are different evidence. Do not close a user's physical-input report solely because a keyboard or pure-model test passed.

Detailed historical test failures, release proofs and activation evidence remain in [`LEARNINGS.md`](../LEARNINGS.md). Current behavior is described in [`navigation-behavior.md`](navigation-behavior.md); the implementation and focused tests remain authoritative for code changes.
